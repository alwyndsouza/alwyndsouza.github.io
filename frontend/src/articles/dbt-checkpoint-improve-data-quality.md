<h3>Overview</h3><p>Data is the lifeblood of good decision-making, but it’s like food: if it’s rotten, it can make you sick. That’s where <strong>data quality</strong> comes in. It’s all about making sure our data is <strong>accurate, consistent, and reliable</strong>.</p><p>As data grows , it becomes more and more difficult to keep up to date with new data models and sources, leading to issues like:</p><ul><li>Metrics calculated incorrectly due to misunderstanding of business or simple error on calculation</li><li>Ambiguous column/table naming. We assume a field means something it doesn’t. Attributes are not easy to discover, causing column duplication</li><li>Documentation on the models not upto date leading to inconsistent understanding and confusions</li></ul><p>Ensuring data quality is crucial because inaccuracies in the data ecosystem can have far-reaching implications. Incorrect data not only erodes trust in the organizational data but also undermines efforts to <strong>foster a>But not all hope is lost, we can still do something to prevent these problems before they arise and that’s where <strong>dbt-checkpoint</strong> can come to our rescue.</p><blockquote>dbt-checkpoint provides <a href="https://pre-commit.com/" title="https://pre-commit.com/" rel="noopener" target="_blank">pre-commit</a> hooks to ensure the quality of your <a href="https://www.getdbt.com/" title="https://www.getdbt.com/" rel="noopener" target="_blank">dbt</a> projects.</blockquote><blockquote><code><em>dbt</em></code> is awesome, but when the number of models, sources, and macros in a project grows, it becomes challenging to maintain the same level of quality across developers.. Users forget to update columns in property(yml) files or add table and column add descriptions. Without automation the reviewer workload increases and unintentional errors may be missed. dbt-checkpoint allows organizations to add automated validations improving your code review and release process.</blockquote><h3>Deep dive into dbt-checkpoint</h3><h3>Install</h3><p>For detailed installation and usage, instructions see <a href="https://pre-commit.com/" title="https://pre-commit.com/" rel="noopener" target="_blank">pre-commit.com</a> site.</p><p><code>pip install pre-commit</code></p><h3>Setup</h3><ol><li>Create a file named <code>.pre-commit-config.yaml</code> in your project root folder.</li><li>Add <a href="https://github.com/dbt-checkpoint/dbt-checkpoint?tab=readme-ov-file#list-of-dbt-checkpoint-hooks" title="https://github.com/dbt-checkpoint/dbt-checkpoint?tab=readme-ov-file#list-of-dbt-checkpoint-hooks" rel="noopener" target="_blank">list of hooks</a> you want to run before every commit. E.g.:</li></ol><pre spellcheck="false">repos:<br />- repo: https://github.com/dbt-checkpoint/dbt-checkpoint<br /> rev: v1.2.0<br /> hooks:<br /> - id: check-script-semicolon<br /> - id: check-script-has-no-table-name<br /> - id: dbt-test<br /> - id: dbt-docs-generate<br /> - id: check-model-has-all-columns<br /> name: Check columns - core<br /> files: ^models/core</pre><p>3. Optionally, run <code>pre-commit install</code> to set up the git hook scripts. With this, <code>pre-commit</code> will run automatically on <code>git commit</code>! You can also manually run <code>pre-commit run</code> after you <code>stage</code> all files you want to run. Or <code>pre-commit run --all-files</code> to run the hooks against all of the files (not only <code>staged</code>).</p><h3>Housekeeping for pre-commit</h3><p><code>pre-commit autoupdate</code></p><p>This command is also useful if you do not know what version is appropriate for the hooks you wish to use. If in doubt. Set rev: 0.0.1 and run pre-commit autoupdate.</p>
