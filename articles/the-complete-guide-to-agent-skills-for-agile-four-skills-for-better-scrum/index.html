The Complete Guide to Agent Skills for Agile: Four Skills for Better Scrum

Most agile teams lose 20–30% of every sprint rewriting stories that were unclear from the start.

I have written Agile Story Skills for :

  • problem‑framing
  • agile-story-writer
  • agile-story-splitter
  • and sprint-goal-writer

using proven agile frameworks directly into your IDE. The output is clean, structured, and ready for Jira, GitHub Issues, Linear, or Azure DevOps.

https://github.com/alwyndsouza/agile-story-skills

Why This Matters

If you have ever stared at a sprint card that says “Improve the dashboard” — no acceptance criteria, no boundaries, no estimate — you already know the pain.

The issue isn’t lazy product owners or disengaged developers. It’s that writing good stories is a craft, and most teams never get formal training. Tools don’t enforce quality. Teams don’t share a consistent mental model. And the backlog becomes a graveyard of ambiguous work.

This article introduces the Agile Story Skills Toolkit — four Copilot Agent Skills that guide a team from a vague request all the way to a sprint goal. This is the overview article in a five‑part series; each of the next four articles dives deep into one skill.

Skill 1 — Problem Framing: Prevent Solving the Wrong Problem

https://github.com/alwyndsouza/agile-story-skills/tree/main/.github/skills/problem-framing

The cheapest defect is the one you never build – and the most expensive is solving the wrong problem entirely.

The problem-framing skill walks teams through the MITRE Problem Framing Canvas:

  • Phase 1 — Look Inward
  • Phase 2 — Look Outward
  • Phase 3 — Reframe

It asks eight structured questions and produces the following:

  • A refined problem statement
  • A “How Might We…” (HMW) question that seeds all downstream stories

Skipping this step means writing beautiful stories for the wrong thing.

Skill 2 — Story Writing: Generate INVEST‑Quality Stories Automatically

https://github.com/alwyndsouza/agile-story-skills/tree/main/.github/skills/agile-story-writer

Once the problem is framed, agile-story-writer produces a complete, unambiguous story using industry-standard patterns:

  • GIVEN / WHEN / THEN acceptance criteria (BDD, per Dan North)
  • Explicit Scope IN / OUT
  • Non‑functional requirements
  • Definition of Ready and Definition of Done
  • Validation against INVEST (Independent, Negotiable, Valuable, Estimable, Small, Testable)

Every story becomes estimable, testable, and sprint‑ready. No more “I’ll know it when I see it.”

Skill 3 — Story Splitting: Break Down 13‑Point Monsters

https://github.com/alwyndsouza/agile-story-skills/tree/main/.github/skills/agile-story-splitter

When a story is too large (>8 points), unclear, or part of an epic, agile-story-splitter applies the eight humanising work split patterns by Richard Lawrence and Peter Green.

These patterns produce vertical slices — each delivering standalone user value.

Patterns include:

  • Workflow steps
  • Business rule variations
  • Data variations
  • Acceptance criteria complexity
  • Major effort
  • External dependencies
  • DevOps steps
  • Tiny acts of discovery

Horizontal splits (backend first, frontend later) Create work that can’t ship. Vertical splits create value.

Skill 4 — Sprint Goal Writing: The Team’s Daily Trade‑off Lever

https://github.com/alwyndsouza/agile-story-skills/tree/main/.github/skills/sprint-goal-writer

Once stories are committed, sprint-goal-writer generates a single, outcome‑based sprint goal aligned with the Scrum Guide.

It runs a five‑item health check to ensure the goal is the following:

  • Specific
  • Outcome‑based
  • Beneficiary‑focused
  • Measurable or directional
  • Useful for trade‑offs

A sprint goal isn’t a ceremony — it’s the compass for every trade‑off the team makes. Article 4 includes a full example and explains the mis‑scoped story flag.

How to install the skills:

Download the repository and copy the four skill directories into:

  • .github/skills/ (repo‑scoped), or
  • ~/.copilot/skills/ (global)
