What We’ll Accomplish

By the end of this article, you’ll have:

  • ✅ A properly structured dbt project
  • ✅ Python dependencies configured
  • ✅ Basic dbt configuration files
  • ✅ GitHub repository ready for CI/CD

Project Structure Overview

Let’s start by understanding the complete project structure we’ll be building:

your-dbt-project/
├── .github/
│   └── workflows/              # GitHub Actions workflows (Article 5)
├── models/                     # Your dbt models
│   ├── staging/
│   ├── intermediate/
│   └── marts/
├── macros/                     # Custom dbt macros
├── tests/                      # Custom dbt tests
├── .pre-commit-config.yaml     # Pre-commit configuration (Article 2)
├── .sqlfluff                   # SQLFluff configuration (Article 3)
├── .sqlfluffignore            # SQLFluff ignore patterns (Article 3)
├── .prettierrc                # Prettier configuration (Article 4)
├── .prettierignore            # Prettier ignore patterns (Article 4)
├── dbt-requirements.txt       # Python dependencies
├── package.json               # npm dependencies (Article 4)
├── dbt_project.yml           # dbt project configuration
└── profiles.yml              # dbt connection profiles

Step 1: Initialize Your dbt Project

If you don’t already have a dbt project, let’s create one:

# Install dbt-core and your adapter (we'll use Databricks)
pip install dbt-core dbt-databricks

# Initialize a new dbt project
dbt init your_project_name
# Navigate to your project
cd your_project_name

Step 2: Python Dependencies Configuration

Create a dbt-requirements.txt file in your project root. This file will contain all the Python packages needed for our CI/CD pipeline:

# dbt-requirements.txt
pre-commit==4.2.0
dbt-core==1.9.8
dbt-databricks==1.9.5
sqlfluff==3.4.1
sqlfluff-templater-dbt==3.4.1

Why These Specific Versions?

  • pre-commit==4.2.0: The latest stable version for managing git hooks
  • dbt-core==1.9.8: Recent stable release with performance improvements
  • dbt-databricks==1.9.5: Compatible adapter version for Databricks
  • sqlfluff==3.4.1: SQL linting with dbt template support
  • sqlfluff-templater-dbt==3.4.1: Enables SQLFluff to understand dbt Jinja

Installing Dependencies

# Create a virtual environment (recommended)
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r dbt-requirements.txt

Step 3: dbt Project Configuration

dbt_project.yml

Your dbt_project.yml should follow this structure for optimal CI/CD integration:

# dbt_project.yml
name: 'your_project_name'
version: '1.0.0'
config-version: 2

# This setting configures which "profile" dbt uses for this project.
profile: 'jaffle_shop_demo'  # Match this with your profiles.yml
# These configurations specify where dbt should look for different types of files.
model-paths: ["models"]
analysis-paths: ["analyses"]
test-paths: ["tests"]
seed-paths: ["seeds"]
macro-paths: ["macros"]
snapshot-paths: ["snapshots"]
clean-targets:
  - "target"
  - "dbt_packages"
# Model configurations
models:
  your_project_name:
    # Staging models
    staging:
      +materialized: view
      +docs:
        node_color: "lightblue"
    
    # Intermediate models  
    intermediate:
      +materialized: view
      +docs:
        node_color: "orange"
    
    # Mart models
    marts:
      +materialized: table
      +docs:
        node_color: "green"
# Test configurations
tests:
  +store_failures: true
  +severity: warn
# Snapshot configurations
snapshots:
  +target_schema: snapshots
  +strategy: timestamp
  +updated_at: updated_at
vars:
  # dbt-utils variables
  'dbt_date:time_zone': 'UTC'

profiles.yml

Create a profiles.yml file in your project root (this is unusual but useful for CI/CD):

jaffle_shop_demo:
  outputs:
    dev:
      type: databricks
      catalog: dev_catalog
      schema: your_schema
      host: "{{ env_var('DBT_DATABRICKS_HOST') }}"
      http_path: "{{ env_var('DBT_DATABRICKS_HTTP_PATH') }}"
      token: "{{ env_var('DBT_DATABRICKS_TOKEN') }}"
      threads: 4

      
    prod:
      type: databricks
      catalog: prod_catalog
      schema: your_schema
      host: "{{ env_var('DBT_DATABRICKS_HOST') }}"
      http_path: "{{ env_var('DBT_DATABRICKS_HTTP_PATH') }}"
      token: "{{ env_var('DBT_DATABRICKS_TOKEN') }}"
      threads: 8

Why profiles.yml in the Project Root?

Normally, profiles.yml lives in ~/.dbt/, but for CI/CD we want:

  • Version control: Configuration changes are tracked
  • Consistency: All team members use the same connection logic
  • Security: Credentials come from environment variables
  • Flexibility: Easy to manage multiple environments

Step 4: Environment Variables Setup

Create a .env.example file to document required environment variables:

# .env.example
# Copy this file to .env and fill in your actual values
# Databricks connection details
DBT_DATABRICKS_HOST=your-databricks-workspace.cloud.databricks.com
DBT_DATABRICKS_HTTP_PATH=/sql/1.0/warehouses/your-warehouse-id
DBT_DATABRICKS_TOKEN=your-personal-access-token

Important: Add .env to your .gitignore to prevent committing secrets!

Step 6: Verify Your Setup

Let’s make sure everything is working correctly:

# Verify dbt can parse your project
dbt parse

# Test your connection (make sure environment variables are set)
dbt debug
# Try running a simple model (if you have any)
dbt run --select models/example

If everything works correctly, you should see:

  • ✅ dbt parse completes without errors
  • ✅ dbt debug shows all connection checks passing
  • ✅ Any existing models compile and run successfully

Common Issues and Troubleshooting

Issue 1: dbt debug fails

Symptom: Connection tests fail Solution:

  • Verify environment variables are set correctly
  • Check Databricks workspace URL format
  • Validate personal access token permissions

Issue 2: dbt parse errors

Symptom: YAML parsing errors Solution:

  • Validate YAML syntax using an online validator
  • Check indentation (use spaces, not tabs)
  • Ensure all referenced models exist

Issue 3: Permission errors

Symptom: Cannot create schemas or tables Solution:

  • Verify Databricks token has correct permissions
  • Check catalog and schema access rights
  • Ensure compute resource is accessible
