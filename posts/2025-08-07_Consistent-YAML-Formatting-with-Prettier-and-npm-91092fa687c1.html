Consistent YAML Formatting with Prettier and npm

Article 4 of 5: Building a Production-Ready dbt CI/CD Pipeline

Welcome back to our dbt CI/CD series! We’ve covered pre-commit hooks and SQL linting. Now we’ll tackle YAML formatting — ensuring your dbt configuration files, model properties, and source definitions are consistently formatted across your entire team.

Why YAML Formatting Matters

In dbt projects, YAML files are everywhere:

  • dbt_project.yml - Project configuration
  • sources.yml - Source definitions
  • models.yml - Model properties and tests
  • profiles.yml - Connection profiles
  • Workflow configurations

Inconsistent YAML formatting leads to:

  • Unnecessary git diffs
  • Merge conflicts
  • Reduced readability
  • Team friction during code reviews

What We’ll Accomplish

By the end of this article, you’ll have:

  • ✅ Node.js and npm set up for your project
  • ✅ Prettier configured specifically for dbt YAML files
  • ✅ Custom formatting rules for different file types
  • ✅ Automated formatting integrated with pre-commit
  • ✅ IDE integration for real-time formatting

Step 1: Set Up Node.js Environment

Install Node.js

If you don’t have Node.js installed:

# Check if Node.js is installed
node --version
npm --version

# If not installed, download from https://nodejs.org/
# Or use a version manager like nvm (recommended)
# Install nvm (Node Version Manager)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
# Install and use Node.js LTS
nvm install --lts
nvm use --lts

Initialize npm in Your Project

# Navigate to your dbt project root
cd your-dbt-project

# Check if package.json exists
ls package.json
# If it doesn't exist, create it (we'll replace the content)
npm init -y

Step 2: Create package.json Configuration

Replace or create package.json in your project root:

{
  "name": "my-project-prettier",
  "version": "1.0.0",
  "description": "Configuration for Prettier in my dbt project.",
  "devDependencies": {
    "husky": "^8.0.3",
    "lint-staged": "^16.1.2",
    "prettier": "^3.6.2"
  },
  "scripts": {
    "format:dbt": "prettier --write './**/*.{yml,yaml}'",
    "format:check:dbt": "prettier --check './**/*.{yml,yaml}'",
    "prepare": "husky install"
  },
  "lint-staged": {
    "./**/*.{yml,yaml}": [
      "prettier --write"
    ]
  }
}

Understanding the Dependencies

  • prettier: The core formatting tool
  • husky: Git hooks manager (alternative to pre-commit for Node.js)
  • lint-staged: Run linters on staged files only

Understanding the Scripts

  • format:dbt: Format all YAML files in the project
  • format:check:dbt: Check if YAML files are properly formatted
  • prepare: Sets up husky git hooks

Step 4: Create Prettier Configuration

Create .prettierrc

Create .prettierrc in your project root:

{
  "printWidth": 120,
  "tabWidth": 2,
  "useTabs": false,
  "semi": true,
  "singleQuote": true,
  "quoteProps": "as-needed",
  "trailingComma": "es5",
  "bracketSpacing": true,
  "bracketSameLine": false,
  "arrowParens": "always",
  "endOfLine": "lf",
  "overrides": [
    {
      "files": [
        "*.yml",
        "*.yaml"
      ],
      "options": {
        "printWidth": 100,
        "tabWidth": 2,
        "useTabs": false,
        "singleQuote": false,
        "bracketSpacing": true,
        "proseWrap": "preserve"
      }
    },
    {
      "files": [
        "dbt_project.yml",
        "profiles.yml"
      ],
      "options": {
        "printWidth": 120,
        "tabWidth": 2,
        "singleQuote": false
      }
    }
  ]
}

Understanding Prettier Configuration

Global Settings

{
  "printWidth": 120,      // Maximum line length
  "tabWidth": 2,          // Number of spaces per tab
  "useTabs": false,       // Use spaces instead of tabs
  "endOfLine": "lf"       // Unix line endings
}

YAML-Specific Settings

{
  "files": ["*.yml", "*.yaml"],
  "options": {
    "printWidth": 100,           // Shorter lines for readability
    "singleQuote": false,        // Use double quotes (YAML standard)
    "proseWrap": "preserve"      // Don't wrap text in comments
  }
}

dbt Configuration Files

{
  "files": ["dbt_project.yml", "profiles.yml"],
  "options": {
    "printWidth": 120,    // Allow longer lines for complex configs
    "tabWidth": 2         // Consistent indentation
  }
}

Step 6: Test Prettier Configuration

Create Sample YAML Files for Testing

Let’s create some poorly formatted YAML files to test our configuration:

Create models/staging/_staging__models_bad.yml:

# models/staging/_staging__models_bad.yml
# This file intentionally has formatting issues
version:    2
models:
- name:   stg_customers
  description: >
    Staged customer data with basic cleaning and standardization.
    This is a longer description that might wrap.
  columns:
    - name: customer_id
      description: 'Unique identifier for customers'
      data_tests:
        - unique
        - not_null
    - name: first_name
      description: "Customer's first name"
    - name:   last_name
      description: "Customer's last name"
      data_tests:
      - not_null
    - name: email
      description: 'Customer email address'
      data_tests:   [unique, not_null]

Test Prettier Formatting

# Check what needs formatting (doesn't modify files)
npm run format:check:dbt
# Actually format the files
npm run format:dbt
# Or format specific files
npx prettier --write models/staging/_staging__models_bad.yml

The file should now be formatted as:

# models/staging/_staging__models_bad.yml
# This file intentionally has formatting issues
version: 2
models:
  - name: stg_customers
    description: >
      Staged customer data with basic cleaning and standardization.
      This is a longer description that might wrap.
    columns:
      - name: customer_id
        description: "Unique identifier for customers"
        data_tests:
          - unique
          - not_null
      - name: first_name
        description: "Customer's first name"
      - name: last_name
        description: "Customer's last name"
        data_tests:
          - not_null
      - name: email
        description: "Customer email address"
        data_tests: [unique, not_null]

Step 7: Integration with Pre-commit

Your pre-commit configuration from Article 2 should already include the Prettier hook:

# In .pre-commit-config.yaml
- repo: local
  hooks:
    - id: prettier-local
      name: Run Prettier via npm
      entry: bash -c 'npm run format:dbt'
      language: python
      types: [yaml]
      pass_filenames: false
      always_run: false
      description: "Ensure npm is installed and run Prettier on the models directory."
      additional_dependencies: [npm]
      stages: [manual]

Test Pre-commit Integration

# Test the prettier hook specifically
pre-commit run prettier-local --all-files --hook-stage manual
# Or test on specific files
pre-commit run prettier-local --files models/staging/_staging__models_bad.yml --hook-stage manual

Step 8: Advanced Prettier Configuration

Custom Rules for Different File Types

You can add more specific overrides:

{
  "overrides": [
    {
      "files": ["*.yml", "*.yaml"],
      "options": {
        "printWidth": 100,
        "tabWidth": 2,
        "singleQuote": false,
        "proseWrap": "preserve"
      }
    },
    {
      "files": ["dbt_project.yml"],
      "options": {
        "printWidth": 120,
        "tabWidth": 2
      }
    },
    {
      "files": ["profiles.yml"],
      "options": {
        "printWidth": 120,
        "tabWidth": 2,
        "singleQuote": false
      }
    },
    {
      "files": [".github/workflows/*.yml"],
      "options": {
        "printWidth": 120,
        "tabWidth": 2
      }
    },
    {
      "files": ["models/**/*.yml"],
      "options": {
        "printWidth": 100,
        "tabWidth": 2,
        "singleQuote": false
      }
    }
  ]
}

Schema-Specific Formatting

For complex dbt schema files, you might want different settings:

{
  "files": ["models/**/schema.yml", "models/**/_*.yml"],
  "options": {
    "printWidth": 90,
    "tabWidth": 2,
    "singleQuote": false,
    "proseWrap": "never"
  }
}

Step 9: IDE Integration

VS Code Integration

  1. Install the “Prettier — Code formatter” extension
  2. Add to your .vscode/settings.json:
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true,
  "editor.formatOnPaste": true,
  "[yaml]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.formatOnSave": true
  },
  "[yml]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.formatOnSave": true
  },
  "prettier.configPath": ".prettierrc",
  "prettier.ignorePath": ".prettierignore"
}
  1. Create .vscode/extensions.json to recommend extensions:
{
  "recommendations": [
    "esbenp.prettier-vscode",
    "ms-python.python",
    "bastienboutonnet.vscode-dbt"
  ]
}

IntelliJ/PyCharm Integration

  1. Install the “Prettier” plugin
  2. Go to Settings → Languages & Frameworks → JavaScript → Prettier
  3. Set Prettier package to ./node_modules/prettier
  4. Set configuration file to .prettierrc
  5. Enable “On ‘Reformat Code’ action” and “On save”

Step 10: Team Workflow Integration

Development Workflow

# Before committing YAML changes:
npm run format:dbt

# Verify formatting:
npm run format:check:dbt
# Then commit (pre-commit will verify formatting)
git add models/
git commit -m "Update customer model properties"

CI/CD Integration

Your GitHub Actions workflow (Article 5) will include:

# Part of the GitHub Actions workflow
- name: Run prettier check on changed YAML files
  run: |
    # Get list of changed YAML files
    CHANGED_YAML_FILES=$(git diff --name-only HEAD~1 | grep -E '.*\.(yml|yaml) || true)
    
    if [ -n "$CHANGED_YAML_FILES" ]; then
      npx prettier --check $CHANGED_YAML_FILES
    fi

Step 11: Common YAML Formatting Patterns

dbt Model Properties

Before Prettier:

version:2
models:
- name:stg_customers
  description:>
    Customer staging table
  columns:
  - name:customer_id
    data_tests:[unique,not_null]

After Prettier:

version: 2
models:
  - name: stg_customers
    description: >
      Customer staging table
    columns:
      - name: customer_id
        data_tests: [unique, not_null]

dbt Source Definitions

Before Prettier:

sources:
- name:raw
  tables:
  - name:customers
    columns:
    - name:id
      data_tests:
      - unique
      - not_null

After Prettier:

sources:
  - name: raw
    tables:
      - name: customers
        columns:
          - name: id
            data_tests:
              - unique
              - not_null

Complex dbt Project Configuration

Before Prettier:

models:
  jaffle_shop:
    staging:
      +materialized:view
      +docs:{node_color:"lightblue"}
    marts:
      +materialized:table
      finance:
        +materialized:table
        +schema:finance

After Prettier:

models:
  jaffle_shop:
    staging:
      +materialized: view
      +docs: { node_color: "lightblue" }
    marts:
      +materialized: table
      finance:
        +materialized: table
        +schema: finance

Step 12: Handling Special Cases

Long Descriptions

Prettier handles long descriptions intelligently:

# Input
models:
  - name: customer_lifetime_value
    description: This model calculates customer lifetime value using a complex algorithm that takes into account purchase history, frequency, and monetary value over time.

# Output (with proseWrap: "preserve")
models:
  - name: customer_lifetime_value
    description: This model calculates customer lifetime value using a complex algorithm that takes into account purchase history, frequency, and monetary value over time.
# Or use YAML block scalars for very long descriptions:
models:
  - name: customer_lifetime_value
    description: >
      This model calculates customer lifetime value using a complex algorithm
      that takes into account purchase history, frequency, and monetary value
      over time. The calculation includes multiple factors and uses advanced
      statistical methods.

Complex Test Configurations

# Before
data_tests:
- dbt_utils.unique_combination_of_columns:{combination_of_columns:[customer_id,order_date],quote_columns:true}
# After  
data_tests:
  - dbt_utils.unique_combination_of_columns:
      combination_of_columns: [customer_id, order_date]
      quote_columns: true

GitHub Actions Workflows

# Before
on:
  push:{branches:[main]}
  pull_request:{branches:[main,dev]}
# After
on:
  push:
    branches: [main]
  pull_request:
    branches: [main, dev]

Step 13: Troubleshooting Common Issues

Issue 1: Prettier not finding configuration

Symptom: Prettier uses default settings instead of your config Solution:

# Verify config file location
ls -la .prettierrc
# Test with explicit config
npx prettier --config .prettierrc --check models/
# Check for syntax errors in .prettierrc
npx prettier --find-config-path models/staging/

Issue 2: npm scripts not working

Symptom: npm run format:dbt fails Solution:

# Verify package.json syntax
cat package.json | jq .
# Reinstall dependencies
rm -rf node_modules package-lock.json
npm install
# Test prettier directly
npx prettier --version

Issue 3: Pre-commit hook fails

Symptom: Pre-commit prettier hook fails in CI Solution:

# In .pre-commit-config.yaml, ensure proper setup
- repo: local
  hooks:
    - id: prettier-local
      name: Run Prettier via npm
      entry: bash -c 'npm ci && npm run format:check:dbt'
      language: system
      types: [yaml]
      pass_filenames: false

Issue 4: Formatting conflicts with dbt

Symptom: Prettier breaks dbt YAML syntax Solution:

// Add to .prettierrc for problematic patterns
{
  "overrides": [
    {
      "files": ["dbt_project.yml"],
      "options": {
        "printWidth": 200,  // Allow longer lines
        "proseWrap": "never"
      }
    }
  ]
}

Step 14: Advanced npm Scripts

Enhanced package.json Scripts

{
  "scripts": {
    "format:dbt": "prettier --write './**/*.{yml,yaml}'",
    "format:check:dbt": "prettier --check './**/*.{yml,yaml}'",
    "format:models": "prettier --write 'models/**/*.{yml,yaml}'",
    "format:sources": "prettier --write 'models/**/sources.yml'",
    "format:dbt-project": "prettier --write 'dbt_project.yml'",
    "format:ci": "prettier --write '.github/workflows/*.yml'",
    "lint:yaml": "prettier --check './**/*.{yml,yaml}' --list-different",
    "prepare": "husky install"
  }
}

Selective Formatting Commands

# Format only model properties
npm run format:models

# Format only source definitions  
npm run format:sources

# Format only CI workflows
npm run format:ci

# Check formatting and list problematic files
npm run lint:yaml

Step 15: Performance Optimization

Speed Up Prettier for Large Projects

{
  "scripts": {
    "format:dbt:fast": "prettier --write './**/*.{yml,yaml}' --cache",
    "format:check:dbt:fast": "prettier --check './**/*.{yml,yaml}' --cache"
  }
}

Parallel Processing

# Install prettier in parallel with other tasks
npm install --save-dev prettier &
npm install --save-dev husky &
wait
# Format multiple directories in parallel
prettier --write 'models/**/*.yml' & 
prettier --write '.github/**/*.yml' &
wait

Step 16: Team Standards Documentation

Create a YAML_STYLE_GUIDE.md in your project:

## Formatting Standards
- **Indentation**: 2 spaces (no tabs)
- **Line Length**: 100 characters for YAML files
- **Quotes**: Use double quotes for strings
- **Arrays**: Use consistent bracket notation for short arrays
## Examples
### Good ✅

models:
  - name: stg_customers
    description: "Staged customer data"
    data_tests: [unique, not_null]

Bad ❌
models:
- name:stg_customers
  description:'Staged customer data'
  data_tests:[unique,not_null]

Tools

  • Run npm run format:dbt before committing
  • VS Code will auto-format on save
  • Pre-commit hooks will catch formatting issues
