What Are Pre-commit Hooks?

Pre-commit hooks are scripts that run automatically before each git commit. They catch issues early, ensuring that problematic code never enters your repository. Think of them as automatic quality gates that enforce standards consistently across your team.

What We'll Accomplish

By the end of this article, you'll have:

  • ✅ Pre-commit framework installed and configured
  • ✅ Basic file validation hooks (whitespace, file size, etc.)
  • ✅ Security scanning with Gitleaks
  • ✅ dbt-specific quality checks with dbt-checkpoint
  • ✅ Local testing and validation workflow

Step 1: Install Pre-commit

If you followed Article 1, pre-commit should already be installed. Let's verify:

# Activate your virtual environment
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Verify pre-commit is installed
pre-commit --version
# Should output: pre-commit 4.2.0

# If not installed:
pip install pre-commit==4.2.0

Step 2: Create Pre-commit Configuration

Create .pre-commit-config.yaml in your project root:

# .pre-commit-config.yaml
# This file configures pre-commit hooks for the dbt project.
# It specifies the hooks to run, their configurations, and the stages at which they should be executed.

fail_fast: false
repos:
  # Basic file validation hooks
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: trailing-whitespace
        files: ^(models|macros|tests)/.*\.(sql|yml|yaml|md)$
        args: [--markdown-linebreak-ext=md]
        stages: [pre-commit, manual]

      - id: end-of-file-fixer
        files: ^(models|macros|tests)/.*\.(sql|yml|yaml|md)$
        stages: [pre-commit, manual]

      - id: check-added-large-files
        files: ^
        args: ["--maxkb=1024"]
        stages: [pre-commit, manual]

      - id: detect-private-key
        files: ^
        stages: [pre-commit, manual]

      - id: check-case-conflict
        files: ^
        stages: [pre-commit, manual]

      - id: mixed-line-ending
        files: ^(models|macros|tests)/.*\.(sql|yml|yaml|md)$
        args: [--fix=lf]
        stages: [pre-commit, manual]

  # Security scanning
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.27.2
    hooks:
      - id: gitleaks
        stages: [pre-commit, manual]

  # YAML formatting (we'll configure this in Article 4)
  - repo: local
    hooks:
      - id: prettier-local
        name: Run Prettier via npm
        entry: bash -c 'npm run format:dbt'
        language: python
        types: [yaml]
        pass_filenames: false
        always_run: false
        description: "Ensure npm is installed and run Prettier on the models directory."
        additional_dependencies: [npm]
        stages: [manual]

  # dbt-specific quality checks
  - repo: https://github.com/dbt-checkpoint/dbt-checkpoint
    rev: v2.0.7
    hooks:
      # Stage 1: Basic parsing and validation
      - id: dbt-parse
        args: ["--cmd-flags", "++profiles-dir", ".", "++project-dir", "."]
        stages: [pre-commit, manual]

      - id: dbt-docs-generate
        stages: [manual]
        #args: ["--cmd-flags","++empty-catalog", "++profiles-dir", ".", "++project-dir", "."]

      # Stage 2: Model testing and documentation checks
      - id: check-model-has-tests
        args:
          [
            "--test-cnt",
            "2",
            "--exclude",
            "dbt_packages|products|locations|supplies|metricflow_time_spine",
            "--",
          ]
        stages: [pre-commit, manual]

      - id: check-model-has-properties-file
        files: ^models
        stages: [pre-commit, manual]

      # Stage 3: Code quality and reference checks
      - id: check-script-ref-and-source
        files: ^models
        stages: [pre-commit, manual]

      # Stage 4: SQL style checks
      - id: check-script-semicolon
        files: ^models
        stages: [pre-commit, manual]

      - id: check-script-has-no-table-name
        files: ^models/
        stages: [pre-commit, manual]

      # Stage 5: Documentation completeness
      - id: check-model-has-description
        files: ^models
        stages: [pre-commit, manual]

      - id: check-model-columns-have-desc
        files: ^models
        stages: [pre-commit, manual]

  # SQL linting (we'll configure this in Article 3)
  - repo: https://github.com/sqlfluff/sqlfluff
    rev: 3.4.1
    hooks:
      - id: sqlfluff-lint
        args: ["--config", ".sqlfluff", "--ignore", ".sqlfluffignore"]
        additional_dependencies: [sqlfluff-templater-dbt, dbt-core, dbt-databricks]
        files: ^models
        stages: [manual]

      - id: sqlfluff-fix
        args: ["--config", ".sqlfluff", "--ignore", ".sqlfluffignore"]
        additional_dependencies: [sqlfluff-templater-dbt, dbt-core, dbt-databricks]
        files: ^models
        stages: [manual]

Understanding the Configuration

Hook Categories

Our configuration includes five categories of hooks:

  1. Basic File Validation: Catches common file issues
  2. Security Scanning: Prevents credential leaks
  3. YAML Formatting: Ensures consistent formatting (Article 4)
  4. dbt-Specific Checks: Validates dbt best practices
  5. SQL Linting: Enforces SQL style standards (Article 3)

Execution Stages

  • pre-commit: Runs automatically before each commit
  • manual: Only runs when explicitly called (useful for heavy checks)

Key Configuration Options

fail_fast: false  # Continue running all hooks even if one fails
files: ^(models|macros|tests)/.*\.(sql|yml|yaml|md)$  # File pattern matching
args: ["--maxkb=1024"]  # Hook-specific arguments
stages: [pre-commit, manual]  # When to run this hook

Step 3: Install Pre-commit Hooks

# Install the pre-commit git hook scripts
pre-commit install

# Install hooks for manual execution
pre-commit install --hook-type manual

This creates git hooks in .git/hooks/ that will run automatically.

Step 4: Understanding Each Hook Category

Basic File Validation Hooks

- id: trailing-whitespace
  files: ^(models|macros|tests)/.*\.(sql|yml|yaml|md)$
  args: [--markdown-linebreak-ext=md]

What it does: Removes trailing whitespace from lines Why it matters: Prevents unnecessary git diffs and maintains clean code

- id: end-of-file-fixer
  files: ^(models|macros|tests)/.*\.(sql|yml|yaml|md)$

What it does: Ensures files end with a newline Why it matters: Unix convention and prevents git warnings

- id: check-added-large-files
  args: ["--maxkb=1024"]

What it does: Prevents committing files larger than 1MB Why it matters: Keeps repository size manageable

Security Scanning with Gitleaks

- repo: https://github.com/gitleaks/gitleaks
  rev: v8.27.2
  hooks:
    - id: gitleaks
      stages: [pre-commit, manual]

What it does: Scans for secrets, API keys, and credentials Why it matters: Prevents accidental credential leaks

Gitleaks detects patterns like:

  • AWS access keys
  • Database connection strings
  • API tokens
  • Private keys
  • And many more...

dbt-Checkpoint Hooks Deep Dive

Let's examine the most important dbt-specific hooks:

dbt-parse

- id: dbt-parse
  args: ["--cmd-flags", "++profiles-dir", ".", "++project-dir", "."]

What it does: Validates that all dbt models can be parsed Why it matters: Catches syntax errors and missing references early

check-model-has-tests

- id: check-model-has-tests
  args:
    [
      "--test-cnt",
      "2",
      "--exclude",
      "dbt_packages|products|locations|supplies|metricflow_time_spine",
      "--",
    ]

What it does: Ensures each model has at least 2 tests Configuration:

  • --test-cnt 2: Minimum test count per model
  • --exclude: Skip checking these model patterns

check-model-has-properties-file

- id: check-model-has-properties-file
  files: ^models

What it does: Ensures each model has a corresponding properties file Why it matters: Enforces documentation and testing standards

check-model-has-description

- id: check-model-has-description
  files: ^models

What it does: Ensures each model has a description Why it matters: Maintains documentation completeness

Step 5: Testing Your Pre-commit Setup

Test Individual Hooks

# Test basic file validation
pre-commit run trailing-whitespace --all-files

# Test dbt parsing
pre-commit run dbt-parse --all-files

# Test security scanning
pre-commit run gitleaks --all-files

Test All Pre-commit Hooks

# Run all pre-commit stage hooks
pre-commit run --all-files

# Run all manual stage hooks  
pre-commit run --all-files --hook-stage manual

Test a Specific File

# Test hooks on a specific file
pre-commit run --files models/staging/stg_customers.sql

    customer_id,

Common Issues and Troubleshooting

Issue 1: dbt-parse fails

Symptom: dbt-parse hook fails with compilation errors Solution:

# Check dbt debug first
dbt debug

# Verify your profiles.yml and dbt_project.yml are correct
# Ensure all referenced sources exist

Issue 2: Gitleaks false positives

Symptom: Gitleaks flags legitimate code as secrets Solution: Create .gitleaksignore:

# .gitleaksignore
# Ignore specific false positives
models/staging/stg_customers.sql:customer_id:1

Issue 3: Hook installation fails

Symptom: pre-commit install fails Solution:

# Ensure you're in a git repository
git status

# Reinstall pre-commit
pip uninstall pre-commit
pip install pre-commit==4.2.0
pre-commit install

Issue 4: Performance issues

Symptom: Pre-commit hooks are too slow Solutions:

  • Move heavy checks to manual stage
  • Use fail_fast: true for faster feedback
  • Limit file patterns with files: regex

Advanced Configuration Tips

Selective Hook Execution

Run specific hooks based on file changes:

bash

# Only run on SQL files
pre-commit run --files "models/*.sql"
# Skip specific hooks
SKIP=gitleaks pre-commit run --all-files
# Run only specific hooks
pre-commit run trailing-whitespace check-yaml

Integration with IDEs

VS Code Integration

Install the “Pre-commit Helper” extension and add to your .vscode/settings.json:

{
  "python.defaultInterpreterPath": "./venv/bin/python",
  "files.trimTrailingWhitespace": true,
  "files.insertFinalNewline": true
}

Git Hooks Bypass

For emergency commits (use sparingly):

# Bypass pre-commit hooks
git commit -m "Emergency fix" --no-verify

# Or skip specific hooks
SKIP=gitleaks,dbt-parse git commit -m "Quick fix"
