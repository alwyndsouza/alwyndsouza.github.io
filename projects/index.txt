13:T8a1,<p>A production-oriented, local-first reference architecture for real-time fraud detection. The system uses <strong>Redpanda</strong> for event transport via the Kafka API, <strong>RisingWave</strong> for continuous SQL and materialized views, <strong>Grafana</strong> for operational dashboards, and a <strong>Python</strong> producer for synthetic banking event generation.</p>
<h2>Architecture</h2>
<p>The pipeline follows a four-stage data transformation model:</p>
<ol>
<li><strong>Producer</strong> — Python generates transactions, logins, card events, alerts, and KYC updates</li>
<li><strong>Event Broker</strong> — Redpanda buffers and distributes events across topics; malformed events route to a Dead Letter Queue</li>
<li><strong>Stream Processing</strong> — RisingWave consumes topics into sources and transforms data through staging, signal, and risk/case materialized views</li>
<li><strong>Observability</strong> — Grafana queries RisingWave directly for live operational dashboards</li>
</ol>
<h2>Fraud Detection Capabilities</h2>
<p>The system implements detection logic for:</p>
<ul>
<li>Velocity bursts and transaction rate spikes</li>
<li>Geographic impossibility checks</li>
<li>Account takeover indicators</li>
<li>Card-not-present transaction anomalies</li>
<li>Brute-force login detection</li>
<li>Structuring and smurfing patterns</li>
<li>Correlated multi-alert analysis</li>
</ul>
